# 制作与转换

## 从已确认视频方案拆分

1. 固定分辨率、帧率、SRT、口播时间线和素材版本。先检查工程是否被用户手动修改，当前成片和工程优先于旧交付稿。
2. 列出画面独立单元和出现区间。文字从绘制层分离，图片保留原文件，人物保留原始视频，原声单列。已在成片烧录的元素无法靠转换恢复，应从制作源码重导出。
3. Three.js 或 Canvas 的复杂效果按单元开关导出：只显示当前单元，透明背景，同一摄像机、尺寸、帧率与时间轴。导出区间以帧编号记录，首尾采用半开区间 `[first, last)`；人物、文字、背景不得夹带进透明单元。
4. 标题、数字、标签和正文字幕写原生文字。画布运动曲线可转换为位置、缩放、旋转关键帧；化简曲线后检查误差和节奏，不统一改成同一种入场动画。
5. 时间不重叠可复用轨道；同时出现的素材保持原有前后关系。复杂三维单元内部不可编辑，应保留源文件供替换渲染。
6. 生成清单，再调用构建、检查、安装。生产交付前用代表构图和短导出验证。

## Alpha 与边缘

静态透明元素优先 PNG；透明动态单元可试 ProRes 4444 MOV。普通 H.264 MP4 不作为本方案的 Alpha 容器。保留色彩空间，不对所有素材无条件预乘。

先在白底、深色底检查源文件，再比较剪映预览与实际导出。straight Alpha 合成为 `RGB*a + bg*(1-a)`；premultiplied 为 `RGB + bg*(1-a)`，解释错配可产生亮边或暗边。

对确认**尚未预乘**的 RGBA 帧，曾使用以下兼容候选：

```text
-vf format=gbrap16le,premultiply=inplace=1,scale=in_range=pc:out_range=tv:out_color_matrix=bt709
-c:v prores_ks -profile:v 4 -pix_fmt yuva444p10le -alpha_bits 16
-color_primaries bt709 -color_trc bt709 -colorspace bt709 -movflags +faststart
```

先做短片段核对，再批量。人物缩窗不要简单缩小整张已烘焙竖屏，应从原片裁取头肩或上半身；透明边缘问题不能直接推出“格式无法分割”或“无法美颜”。

## 学习用户精修后的差异

对照最初成片、上一交付工程、用户当前工程和最终成片。时长或剪辑有变化时按内容对齐，不能只对相同秒数截图。

从工程读取真实的文字、字号、字形、缩放、位置、阴影、分段与素材层级；从视频逐帧检查实际呈现。全帧缩略图用于覆盖检查，关键时刻用原分辨率核对，不把抽样误称逐帧观看。

记录可复用偏好：常规字与强调字的比例、字幕安全区、重点词配色、断句节奏、人物窗口和实拍素材使用方式。把构图相关的例外也记下来，避免一个数字约束所有版面。复合片段可能是用户绕过编辑问题的手段，不能倒果为因。

## 交付边界

打包素材与字体只代表本地可移植性，不授予其再分发许可。新建副本保留原稿；核对全部素材路径，包括原生文字 `content` 内嵌 JSON 的字体路径。复制可变 JSON，不对其做硬链接。真实人物、用户成片和工程仅保留在用户授权的本地目录。
