# 制作与转换

## 从已确认视频方案拆分

1. 固定分辨率、帧率、SRT、口播时间线和素材版本。先检查工程是否被用户手动修改，当前成片和工程优先于旧交付稿。
2. 列出画面独立单元和出现区间。文字从绘制层分离，图片保留原文件，人物保留原始视频，原声单列。已在成片烧录的元素无法靠转换恢复，应从制作源码重导出。
3. Three.js 或 Canvas 的复杂效果按单元开关导出：只显示当前单元，透明背景，同一摄像机、尺寸、帧率与时间轴。导出区间以帧编号记录，首尾采用半开区间 `[first, last)`；人物、文字、背景不得夹带进透明单元。
4. 标题、数字、标签和正文字幕写原生文字。画布运动曲线可转换为位置、缩放、旋转关键帧；化简曲线后检查误差和节奏，不统一改成同一种入场动画。写入前运行 `normalize_geometry`，修复已有几何动画却缺少 X/Y 位置轴的片段；用 `validate_geometry` 检查有限值、时间与轴完整性，不修改已有动画的含义。具体故障依据见 [兼容记录](compatibility.md#奇偶帧跳动与几何关键帧)。
5. 基础字幕和人物各优先单轨，只有实际遮挡或时间重叠要求才分轨。非重叠素材共轨，同时出现的素材保持前后关系。辅助复合按下述小模块规则整理，内部仍保留独立图、文字和效果；人物与基础字幕外露，不烘焙整页。复杂三维单元内部不可编辑，应保留源文件供替换渲染。
6. 对已确认的视频生成清单，再调用构建、检查、安装；转换、排障和验收均只使用后台文件、脚本与用户提供的导出，禁止任何前端电脑操作。用户要求先审预览时，等待前序视频制作流程完成并获确认后再转换。交付后提示用户自行重启剪映、检查或导出新草稿。

## 小模块复合

以用户后期会一起移动、替换或改字的对象为一个模块，按内容命名，例如“伤口｜图片与标签”。四格适应症应分成四个组，各含自己的图片、底板、阴影和标签；不能整页合包，也不能按“人物前方／后方”或一大段时间把不同模块混包。主图与解释它的局部放大、连线和圈注可同组，前提是属于同一内容。

- 先列模块成员和出现区间，再分配轨道。底板、阴影、局部标签和圈注按制作源码中的对象 ID、显式关联及时间区间归属到图片；动画拆出的多个底板片段也须完整归入该模块。同名文件或相邻轨道不能单独作为归属依据，来源不足时先核对实际画面，不猜配对。
- 跨多个模块的长文字、章节标题和公共说明留在外层；全局背景、人物、基础字幕保持独立。模块内文字仍为原生文字，图、底板、阴影等仍可分别编辑。
- 模块完整与原遮挡关系优先于最少轨数。非重叠模块可共轨；若与外层人物或文字交错遮挡，无法用一个复合保留效果，保留该模块的原始分层并说明，不把其底板塞进另一模块或改动画面来压轨。
- 交付前递归展开复合，恢复全局目标时间，核对原片段无遗漏、无重复，源区间、关键帧、裁切、文字样式和音频设置保持；仅允许必要的局部目标起点与轨道索引变化。检查同轨重叠、模块成员归属和原有遮挡关系。帧级几何检查不等于宿主逐帧渲染验证，需要宿主证据时由用户自己预览或导出。

已适配原生复合时，保留原画布尺寸与帧率；外层使用恒等变换并清除模板遗留动画，内层只将片段目标开始时间减去复合起点，保留源区间和原关键帧时间。媒体关键帧使用源时间，文字使用片段局部时间，不能将所有关键帧一并减去复合起点。没有素材跨越的边界才可直接分组；跨界裁分需单独处理并验证。完整复制复合模板所需的素材及辅助引用，不能只复制可见图片。每层首个有内容的可视轨为唯一主轨，其他可视轨为副轨；递归检查引用、时长、镜像和关键帧。普通 manifest 不自动完成这种复杂转换。

## Alpha 与边缘

静态透明元素优先 PNG；透明动态单元可试 ProRes 4444 MOV。普通 H.264 MP4 不作为本方案的 Alpha 容器。保留色彩空间，不对所有素材无条件预乘。

先在白底、深色底检查源文件；需要宿主对照时，由用户自己预览或导出，再后台分析其提供的文件。straight Alpha 合成为 `RGB*a + bg*(1-a)`；premultiplied 为 `RGB + bg*(1-a)`，解释错配可产生亮边或暗边。

对确认**尚未预乘**的 RGBA 帧，曾使用以下兼容候选：

```text
-vf format=gbrap16le,premultiply=inplace=1,scale=in_range=pc:out_range=tv:out_color_matrix=bt709
-c:v prores_ks -profile:v 4 -pix_fmt yuva444p10le -alpha_bits 16
-color_primaries bt709 -color_trc bt709 -colorspace bt709 -movflags +faststart
```

先做短片段核对，再批量。人物缩窗从原片裁取完整头顶、颈肩或上半身，不简单缩小整张已烘焙竖屏；透明边缘问题不能直接推出“格式无法分割”或“无法美颜”。

## 学习用户精修后的差异

对照最初成片、上一交付工程、用户当前工程和最终成片。时长或剪辑有变化时按内容对齐，不能只对相同秒数截图。

从工程读取真实的文字、字号、字形、缩放、位置、阴影、分段与素材层级；从视频逐帧检查实际呈现。全帧缩略图用于覆盖检查，关键时刻用原分辨率核对，不把抽样误称逐帧观看。

记录可复用偏好：常规字与强调字的比例、字幕安全区、重点词配色、断句节奏、人物窗口和实拍素材使用方式。把构图相关的例外也记下来，避免一个数字约束所有版面。复合片段可能是用户绕过编辑问题的手段，不能倒果为因。

## 保存位置与迁移

1. 用户已确认默认放在剪映下面，不再询问保存位置。读取该电脑实际草稿根目录；安装为新工程创建 `.codex-media/<新 UUID>/` 固定资源根，使媒体绝对引用独立于显示名称与工程目录名。用户另行指定位置时按新要求适配，不把临时工作区、下载目录或移动设备作为最终依赖。
2. 工程内的 `materials` 仍保留视频、图片、音频、SRT、可本地备份字体及必要渲染单元的完整副本，制作源码另附目录。`resource_manifest.json` 记录固定资源根及相对文件名、大小、SHA256；检查时要求实际非官方引用位于固定根，并严格核对清单集合与两份资源的大小、哈希，不能退回工程备份路径掩盖错误。只复制，不移动或删除原素材；仍有草稿依赖时不得删除 `.codex-media`，也不能只移动工程文件夹就假定引用自动迁移。
3. 遍历主时间线、全部复合片段、富文本内嵌字体和算法处理结果，生成实际依赖清单，记录包内路径、大小和校验值。相同文件可以去重；同名不同内容不能覆盖。官方特效缓存可能是目录，检查存在性不能一律使用 `is_file()`。本地字体、官方效果资源及需在新电脑重新下载的依赖分别说明，不能声称仅复制视频就已打包全部效果。
4. 工作草稿使用绝对引用时，不可让“素材已集中”代替路径检查。剪映内改名与磁盘目录改名都可能移动含名称的素材目录，而宿主未完整改写主时间线、复合、字体或算法引用。每次改名、恢复、迁移分别验证；历史成功不泛化。当前已修好的复杂工程不自动迁移，用户测试期间不改工程、素材或索引；另做迁移须在新副本保留时间线和效果。
5. 交付前确认没有缺失引用和意外依赖临时目录。需要改名或迁移验证时，准备隔离副本，由用户自己关闭重开、在剪映内改名并检查。跨电脑移动整个项目包后，后台按新根目录迁移路径并核对依赖；没有用户的字体、特效、复合片段及短导出证据时，明确软件兼容未验证。“集中到一个文件夹”本身不代表绝对路径可自动迁移。
6. 用户要求云迁移验证时，由用户自己上传、下载成独立副本并检查或导出；代理只后台核对用户提供的文件，不操作剪映云功能。未完成往返验证时明确云迁移未验证，并保留本地完整包；上传成功或本机预览成功不能代替跨电脑验证。GitHub 同步仅包含 Skill，不上传真实媒体或工程。

安装先在同一磁盘卷、宿主监控根目录外组装完整工程并检查，再原子发布到目标目录，避免宿主读到半成品；不启动、激活或强退剪映。固定资源根降低名称变化对媒体路径的影响，不保证宿主云端打包行为；迁移到新电脑仍须依据完整副本和清单重建引用并由用户实测。

涉及工程内容的修复只在副本进行。先备份当前版本及索引；绝对路径、素材占位符和嵌套草稿路径分别处理，不能把同一个占位符全局替换为某一个素材。首页未显示新工程时检查实际根索引的路径和 ID 绑定；首页 `draft_id` 与内部时间线 ID 不必相等，不为对齐两者覆盖 metadata。需要修改索引则请用户正常退出剪映，备份并保留其他条目，禁止强退。生成和文件校验无需退出剪映；用户继续剪辑时暂缓首页登记。

首页 ID 与时间线 ID 不同时，使用 `python scripts/draft_tool.py check <工程目录> --home-index <root_meta_info.json>` 提供实际绑定证据；命令只读，不修写索引。安装保存的 `delivery_snapshot.json` 只记录当时交付结构。宿主加密保存后保留当前文件、该快照、构建报告及用户确认；读取受限时不把旧明文写回当前稿，也不把快照声称为用户最新编辑版本。

## 资源路径恢复

`scripts/recover_media_paths.py` 用于“改名后的资源仍完整，但旧绝对引用失效”这一支路。先预览恢复计划，核对来源、目标、大小和 SHA256，再明确应用；只补资源，不改工程内容。

```text
python scripts/recover_media_paths.py verified_snapshot.json current_project legacy_project
python scripts/recover_media_paths.py verified_snapshot.json current_project legacy_project --apply --report new_recovery_report.json
```

三个位置参数依次是已验证的历史明文快照、当前工程目录、历史工程目录。默认 dry-run；`--apply` 才补文件，报告路径必须是新文件。先检查计划，再执行已经授权的恢复。工具仅从当前工程读取资源、补回历史 `materials` 路径，不回写当前或旧主稿、metadata、时间线和首页索引。

1. 备份当前改名目录、加密主稿及 metadata、首页索引，记录哈希。旧明文快照只用来提取历史依赖路径，不能作为当前剪辑内容的替代品。
2. 按历史路径找到当前资源，逐文件核对哈希；缺失、来源不唯一或目标内容冲突时停止该项，不覆盖现有文件。不把同一个文件填给所有失效引用。
3. 经预览确认后，仅恢复有证据的旧媒体、字体或处理资源路径。旧名位置只形成资源目录，不放入旧主稿、metadata 或时间线，不登记伪旧工程，不移动或删除当前素材。
4. 再核对复制文件和当前工程/索引哈希。由用户自己重开当前改名稿并确认或导出；分别记录资源路径恢复、用户修改保留及宿主可用结果。此方法兼容既有绝对引用，不保证再次改名或云端迁移。

2026-10-14 案例按此原则恢复 117 个资源，用户确认“已恢复”。工具计划、报告与原始工程仅保留在用户授权的本地目录；Skill 仓库仅收录通用脚本和合成测试，不上传真实项目 JSON。

## 交付边界

打包素材与字体不授予其再分发许可，也不能替代路径迁移及新电脑验证。新建副本保留原稿；核对全部素材路径，包括原生文字 `content` 内嵌 JSON 的字体路径。复制可变 JSON，不对其做硬链接。真实人物、用户成片和工程仅保留在用户授权的本地目录；云端上传需用户明确授权。
